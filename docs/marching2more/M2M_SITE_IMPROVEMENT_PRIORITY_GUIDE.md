# Marching 2 More — Site Improvement Priority Guide

## Purpose
This document answers the simple question:
**what actually matters next?**

It exists so we do not keep polishing random surfaces just because they are available to polish.
The goal is to keep the site moving in the right direction, with work that improves clarity, trust, conversion, mobile usability, and long-term maintainability.

## North star
A good Marching 2 More website should help a visitor do four things quickly:
1. Understand who the site is for.
2. Understand what the team helps with.
3. Trust the brand enough to keep going.
4. Know the next step without thinking too hard.

If a change does not help one of those, it is probably lower value.

## What matters most

### 1. Clarity before decoration
The site should be easy to understand before it is impressive.

Prioritize:
- homepage messaging
- route purpose clarity
- hero hierarchy
- CTA language
- navigation logic
- section sequencing

This is the difference between a site that looks nice and a site that actually helps.

### 2. Mobile usability
Mobile is not a cleanup lane.
It is the default reality for a real estate website.

Prioritize:
- readable type scale
- strong spacing rhythm
- clear button sizes
- usable forms
- no horizontal overflow
- predictable stacked layouts
- well-framed media
- limited text walls

If a page is pretty on desktop but frustrating on a phone, it is not finished.

### 3. Conversion flow
The site should gently guide visitors toward action.

Prioritize:
- fewer competing CTAs
- clearer primary vs secondary actions
- stronger trust cues near forms
- better success and error states
- better lead capture hierarchy
- better pathing from awareness to action

The goal is not aggression.
The goal is fewer dead ends.

### 4. Trust and credibility
Real estate is trust-heavy.
The site should feel calm, competent, and human.

Prioritize:
- team presence
- social proof
- service framing
- support language near contact surfaces
- clean visuals around credibility sections
- consistent brand tone

### 5. Shared system consistency
The site gets better when the same patterns are reused well.

Prioritize:
- shared button hierarchy
- shared form behavior
- shared card and panel treatment
- shared image framing
- shared hero logic
- shared spacing and width rules

This keeps the site from feeling like 20 separate mini-sites.

### 6. Foundation hygiene
The repo should stay readable as the site grows.

Prioritize:
- docs that match reality
- fewer duplicate explanations
- fewer stale placeholders
- fewer conflicting “source of truth” docs
- clearer route and component naming
- less copy drift

Good docs reduce bad decisions.

## What to do next, in order

### P0
- Make homepage, nav, and key CTAs easier to understand.
- Fix mobile pain points on the highest-traffic pages.
- Clean up conversion surfaces and forms.
- Reduce any obvious trust friction.

### P1
- Tighten shared components and page patterns.
- Improve secondary routes once the main flow is clear.
- Clean up documentation drift and placeholder language.
- Normalize spacing, cards, and media treatment.

### P2
- Polish lower-traffic pages.
- Add subtle visual richness only after clarity and flow are solid.
- Do aesthetic upgrades that support comprehension, not distraction.

## What not to do
- Do not redesign just to redesign.
- Do not add new libraries unless absolutely necessary.
- Do not create more docs that repeat the same thing in a new voice.
- Do not polish low-value surfaces before fixing the main journey.
- Do not add animation or decoration that does not help understanding or trust.
- Do not change backend behavior just because a visual change is available.

## Decision test
Before shipping a change, ask:
- Does this help someone understand the site faster?
- Does this make mobile easier?
- Does this improve trust?
- Does this improve conversion clarity?
- Does this make the repo easier to maintain?

If the answer is no across the board, skip it.

## Working principle
The best improvements here are usually not dramatic.
They are the boring, high-leverage fixes:
- clearer hierarchy
- better spacing
- stronger mobile behavior
- cleaner docs
- fewer contradictions
- calmer, more obvious next steps

That is how the site becomes better overall.
